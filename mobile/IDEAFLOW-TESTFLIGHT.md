# Buzz Ideaflow for TestFlight

This distribution uses `app.ideaflow.buzz.mobile` on IdeaFlow team `JESMXK96LG`, with the home-screen name **Buzz Ideaflow**. It installs alongside the official mobile app. Its notification extension is `app.ideaflow.buzz.mobile.NotificationService`; its App Group and keychain namespace are isolated under the fork identifier. It registers `buzz-ideaflow://`, keeps canonical Buzz links readable inside the app, and leaves the official `buzz://` handler to the official app.

Build from a real shallow Git checkout at the exact released commit; an archive without Git metadata is rejected. The manifest must cover every tracked file, match the clean commit and retain its digest in the receipt. Release inputs come from the frozen source manifest and the repository's pinned Flutter 3.41.7 toolchain. Keep `pubspec.lock` and `ios/Podfile.lock` unchanged. Do not replace a shared system Flutter installation.

Apple setup needs a new App Store Connect app record, the parent and NotificationService bundle IDs, and `group.app.ideaflow.buzz.mobile` assigned to both IDs. Use one manual iOS App Store profile per target, both tied to the existing IdeaFlow Apple Distribution certificate. The extension requires its own profile; it does not require a new certificate. Preserve production App Attest/APNs, declared-age-range and Communication Notifications capabilities authorized by the source entitlements. Stop if Apple asks for account login, a password, 2FA or new membership/terms acceptance.

The release helper `scripts/ideaflow/mobile-archive.sh` requires an authenticated Aqua session and the shared `~/.local/state/ios-build-slot.lock.d` lease owned by this task. It validates exact profile/team/certificate/group entitlements, writes only the build checkout's ignored AppOverrides, uses the frozen dependency locks, uses a fresh invocation directory and an explicit checked Xcode export to avoid accepting stale IPAs, exports a manual App Store IPA and records source/version/hash. The intended first fork marketing version is 0.1.0; select the build number only after reading the actual App Store Connect record. Upload and TestFlight internal delivery follow verification, using the existing host-local ASC key. No keys or signing credentials belong in this repository or leave M5.

The compiled default community is `https://jprojects.communities.buzz.xyz`. This build does not configure a push gateway, so mobile Settings reports push unavailable, as upstream supports. The relay configuration is unchanged. Pair the app with the user's existing identity through the normal device-pairing/onboarding flow; never bake a user's private key into an IPA.

Native builds follow the root-owned Apple queue after the desktop update. Keep other apps/builds and their leases intact. An uploaded build is not a delivered TestFlight build until processing is VALID, its correct internal group is linked, and Jacob's tester access is verified. Do not create a public beta link or submit a public App Store release as part of this task.
