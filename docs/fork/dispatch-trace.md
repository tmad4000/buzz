# Same-channel dispatch traces — §6A

An explicit main-composer “Send to thread…” choice carries one signed `origin` tag: `["origin", channelId, "main"]`. Ordinary Send, New message, editing, inline/thread reply composers and canceled picker interactions add none. The existing NIP-10 destination, author, mention/media preparation, durable queue admission and draft recovery remain authoritative. `localSendOrigin` remains device-local presentation state; it is not repurposed as shared provenance.

The tag enters the captured mention/media flow and immutable outbox tags. Editing a queued body retains its original origin and cannot introduce or move provenance. A dedicated optional native `dispatchOriginTag` argument validates exact shape, the current channel UUID, kind9 and a reply parent before signing. It cannot inject h/e/p tags or widen audience. The old IPC argument behavior remains unchanged when provenance is absent. The native implementation and frontend must ship together; native compilation and actual IPC acceptance are separate gates.

In the normal threaded channel view, committed loaded replies carrying valid same-channel provenance gain a tiny derived trace at their own signed time. Expand renders the same source body/attachments read-only; Open uses the existing guarded exact-root/reply path. It never creates a second content event. Source ID, edit overlay and deletion semantics stay canonical. Unknown, foreign, duplicate-scope, pending and local-outbox provenance does not render. Missing roots reveal no invented title/link. The thread side labels the source “Written in #channel main.”

The composer’s Dispatched button lists loaded traces newest first, independently of Timeline/Threads presentation. These rows do not mount MessageRow/read observers or expose reactions/replies/mention controls. Virtualized row-to-message read admission excludes the trace, and the trace cannot introduce an unread divider or affect grouping. In flat Timeline mode the actual source reply is already present and is not duplicated with a stub. No new unread/mention/count event is published. The existing actual reply still has its normal unread/mention behavior.

Scope is loaded history, just like the current picker: this slice adds no unbounded scan or additional reader endpoint. A trace is visible wherever its committed source event is loaded/retained by the existing authenticated channel window. If a refresh/window excludes it, the loaded-only Dispatched log does not claim full history. Full cross-device/history enumeration requires the shared reader/index contract; it is not fabricated from device-local receipts.

## Later §6B (not in this slice)

Answers & Updates must transclude by the canonical source event ID, not quote/re-sign/repost its body. A separate signed reference can have a reference-event ID, but displayed content/reactions/replies/edit/delete identity stays the source ID. Shared Build13 kind/tag/projection authority and signed source+target scope need confirmation through coordinator067 (all075 requests through that coordinator). The old Build13 wider-audience kind9 body-mirror fallback conflicts with this strict usecase and is excluded. Writer and reader authority must fail closed on fresh complete source/target roster or visibility changes, and reference writes must not redeliver mentions/unread. No listener or live-relay edit is included here.

## Acceptance after captain lane release

Use the real app: route a main draft (with mention and attachment) to an existing thread; verify exactly one published source, one matching trace and one thread-side origin line. Confirm zero sends on picker open/Escape/restore, and no new origin on ordinary Send or nested choices. Expand/collapse and open a trace; ensure the draft is untouched and the exact source reply opens without toggling an already open thread closed. Reading/expanding a stub must not consume reply unread state or duplicate mention delivery. Edit/delete the source: expanded content updates/deletion removes it. Switch flat/threaded views: no duplicate source row, Dispatched still lists loaded traces. Test same chat in two panes and ownership takeover with the existing stale-callback matrix. Reject injected/foreign h/origin claims. Full-history and native/live-relay behavior remain unverified until explicitly exercised.
